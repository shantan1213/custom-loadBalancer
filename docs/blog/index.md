# Building a Custom Spring Boot Load Balancer

Hey, welcome! This is where I’m documenting my Spring Boot load-balancer
project as I build it. I started with a simple question: can I send one request
to my own service and have it pass that request along to a backend? Along the
way, I’ve added two backend apps, H2 databases, create/update endpoints, and
some useful error handling.

> **Project status:** The proxy currently forwards requests to backend 1 only.
> Backend 2 is up and running as a separate service, but I haven’t implemented
> automatic load distribution or failover yet. So, for now, this is more
> accurately a request proxy than a full load balancer.

## What I’ve built so far

There are three Spring Boot apps in this setup. I run each one separately:

| Application | Local address | Responsibility |
| --- | --- | --- |
| My load balancer | `http://localhost:8080` | Takes a request and forwards it to backend 1 |
| Backend 1 | `http://localhost:11111` | Creates and updates users in its H2 database |
| Backend 2 | `http://localhost:22222` | A second user service with its own H2 database |

Each backend has its own in-memory H2 database. That means data created in
backend 1 won’t show up in backend 2, and the data is cleared when that backend
stops. It’s convenient for learning and local testing, but not meant for
permanent storage.

## Following a request

Here’s what happens when I create a user through the proxy: I send JSON to the
load balancer, `ProxyController` receives it, `ProxyService` hands it off, and
`RequestForwarder` sends it to backend 1. Backend 1 checks the names, saves the
user, and sends its response back through the proxy.

```text
Me (the client)
  -> POST /proxy/create
  -> My app at localhost:8080
  -> Backend 1 at localhost:11111, endpoint /create
  -> H2 saves the user
  <- The saved user comes back with an ID
```

Updating a user takes the same trip, this time using `PUT /proxy/update/{id}`.
If I try an ID that doesn’t exist, the backend responds with `404 Not Found`.

## Getting it running

I start each app in its own terminal. The Maven wrapper takes care of running
the project’s Maven build. Make sure the JDK matches the module: the load
balancer and backend 1 currently specify Java 25, while backend 2 specifies
Java 21.

```powershell
# Backend 1
cd C:\Projects\backend\serverone\backend
.\mvnw.cmd spring-boot:run

# Backend 2
cd C:\Projects\backend\servertwo\backend2
.\mvnw.cmd spring-boot:run

# My load balancer
cd C:\Projects\Custom-LoadBalancer
.\mvnw.cmd spring-boot:run
```

The backend addresses are in
`src/main/java/com/platformdaemon/customloadbalancer/requestproxy/BackendServerConstant.java`.
I’ve set up both addresses there, but the current `ping`, `create`, and
`update` proxy calls still go to backend 1.

## Let’s try it

### First, check the connection

```powershell
curl.exe http://localhost:8080/proxy/ping
```

If everything is running, I should see:

```text
pong
```

### Create a user

I send a first and last name to the proxy:

```powershell
curl.exe -X POST "http://localhost:8080/proxy/create" `
  -H "Content-Type: application/json" `
  -d "{\"firstName\":\"Alex\",\"lastName\":\"Kim\"}"
```

The response includes an `id` generated by the backend. I use that ID for the
next request.

### Update a user by ID

I replace `1` below with the ID I got back from creating the user:

```powershell
curl.exe -X PUT "http://localhost:8080/proxy/update/1" `
  -H "Content-Type: application/json" `
  -d "{\"firstName\":\"Jamie\",\"lastName\":\"Park\"}"
```

Both names have to be present and non-blank. If I send invalid JSON or leave a
name blank, the API responds with `400 Bad Request`. An ID that isn’t in the
database gets `404 Not Found`.

## Taking a peek at H2

I can open either backend’s H2 console in a browser:

- Backend 1: `http://localhost:11111/h2-console`
- Backend 2: `http://localhost:22222/h2-console`

For the login, I use JDBC URL `jdbc:h2:mem:testdb`, username `sa`, and leave
the password empty. I need to connect to the backend I actually want to
inspect, since the two apps don’t share a database.

## Handling the not-so-happy paths

I also wanted errors to be useful instead of confusing. Both backends return
Spring `ProblemDetail` responses for things like invalid input, broken JSON,
unsupported methods, missing resources, and database conflicts. Unexpected
errors are logged on the server; the client gets a generic
`500 Internal Server Error` rather than an exposed stack trace.

If my load balancer can’t connect to backend 1, it responds with
`503 Service Unavailable`. That’s a reminder to check that the backend is
running on the configured port.

## Things I’m learning along the way

Building this has helped me see how a few Spring pieces fit together:

- A Spring MVC controller takes the incoming HTTP request and reads its JSON
  body.
- Keeping controller, service, and forwarding logic separate makes it easier
  to follow what happens to the request.
- `RestClient` sends the request to a backend and lets me return its status,
  headers, and response body to the caller.
- Spring Data JPA and H2 give me a quick way to save and inspect records while
  developing.
- Bean Validation catches blank names before they get saved.
- `@RestControllerAdvice` gives my services a consistent way to explain errors.

## What I want to build next

The big next step is to actually distribute requests across both backends.
I’ll need to decide how to pick a server, figure out what happens when one is
down, and write tests to make sure requests go where I expect. Once that’s
working, this will be a proper load balancer rather than just a proxy pointing
at backend 1.
